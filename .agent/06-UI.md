# 06 — UI behaviour

**What it looks like is decided in [design/](design/README.md)** (tokens, illustrations, every
screen for desktop and mobile). This file describes behaviour and where each piece of data comes
from. If the two disagree on looks, the design wins; on behaviour, this file wins.

Desktop-first (check at **1440×900**), must also work at **390×844**. Light/dark follows the system.
Dates and times are shown in `APP_TIMEZONE` (Asia/Dhaka).

## Shell (design: every screen)
- Desktop (≥ 768 px) `AppHeader`: `Logo` + "Vocab" (serif) · tabs **Learn · Words · Review** · keyboard
  button (opens the shortcuts dialog) · avatar button "R" (menu with one item: **Log out**).
- Mobile (< 768 px): `MobileHeader` (logo + page title, page actions on the right) and a bottom `TabBar`.
  During a review session the tab bar is hidden and the header shows ✕ (end session) + progress bar + "4 / 7".
- Review tab badge (marigold) = `dueNow` from `GET /api/words/stats`; hidden when 0. Refresh it after
  saving a word, after a repeat lookup and after each answer.
- `PageDecor` corners as listed in the design README. Never above content, never interactive.

## `/login` (design: D01, M01)
- `book-sprout` illustration, "Vocab", "Sign in to continue", email, password, **Sign in**.
- Wrong credentials → danger banner "Wrong email or password. Try again." above the button.
- No sign-up link, no "forgot password". Logged-in users visiting `/login` go to `/`.

## `/` — Learn
### Empty state (design: D03) — no messages in the current chat
- `book-sprout` illustration, "Met a new word?", one line of help text.
- Two small cards: "**N saved today** · T words in total" (from stats `savedToday`, `total`) and
  "**N due for review** · About M minutes →" (`dueNow`; minutes = `ceil(min(dueNow, 15) × 25 s / 60)`,
  at least 1). The second card links to `/review`. Hide it when `dueNow = 0`.
- "Recently saved": the last 4 saved words (`GET /api/words?range=all&page=1`, first 4) as chips;
  clicking one looks it up (instant, from the saved card). Hide the block when there are no words.
- With zero saved words: only the illustration, title and help text.

### Conversation (design: D02, M02)
- Content column max 760 px, centred. Composer fixed at the bottom, **autofocused**, placeholder
  "Look up a word, or ask about the current one…" (mobile: "Look up a word…").
- Under the composer: "Bangla" switch (remembered in `localStorage`, default on), "New chat"
  (desktop; on mobile it's the pencil icon in the header), and the shortcut hint (desktop only).
- The send button is muted while the input is empty.
- `?q=<word>` on load → runs the lookup immediately (browser address-bar shortcut).
- Loading: a skeleton card appears instantly under the user's message; the composer stays usable.
- Error: danger banner with **Retry** in place of the card.

### Word card (`WordCard`, also used on Words pages)
- Sections in this order, each hidden when empty: headword + part of speech + register chips,
  meaning, Bangla line (hidden when the switch is off), How it's used, Collocations (chips),
  Patterns, Examples (every form of the headword wrapped in the highlighter mark), Don't confuse.
- Save button (top right): `Save Ctrl S` → `Saving…` → `Saved` (or `Updated` when the word existed).
  A card that is already saved shows `Saved` from the start. Success also shows a toast "Saved “word”".
- Banners above the card:
  - repeat lookup counted (`repeatCounted: true`): accent banner "You've looked this up **N times**. It's back in today's review."
  - saved card, not counted (within 12 h): neutral banner "Saved on 12 Oct. You looked it up earlier today."
  - not a real word: warn banner "“recieve” isn't a word. Did you mean **receive**?" — clicking the suggestion looks it up; Save is hidden.
- Reply bubbles (`type: "reply"`): small label "Reply · <currentWord>", plain text paragraphs.
- Follow-ups automatically send `currentWord` = the word of the latest word card.

## `/words` — Words (design: D04, M03, M04)
- `ProgressStrip` from stats: Total · New · Learning · Mastered · **Due now** (highlighted) · Reviewed today.
  Mobile shows the same six as a 3×2 grid ("Reviewed" as the short label).
- Segmented tabs with counts: Today · Week · Month · All (default: **Week**). Search box filters within the tab (debounced 250 ms).
- List grouped by "Today" / "Earlier this week" / "Earlier this month" / month names for older.
  Row: status dot, word, part-of-speech abbreviation (adj, noun, verb, adv, prep, conj, interj, pron, phrase),
  short meaning (one line, ellipsis), right side: `↺ N` badge when `lookupCount > 1`, else the time
  (today: `10:42`; this week: weekday `Sun`; older: `12 Oct`).
- Desktop: two panes. Clicking a row shows its `WordCard` (with `Saved` chip, no Save button) and the
  `WordStats` panel: status + "Box N of 5" + `BoxMeter`, next review date (`Tue, 21 Oct`; "Today" when due),
  looked up N times, right/wrong counts, saved date, last 3 answers (✓/✗ + kind + date), **Delete word**.
  The first row is selected on load.
- Mobile: tapping a row opens `/words/[id]` (compact stats strip on top, card below, delete icon in the header).
- Delete: confirmation dialog "Delete *cohesive*? Its review history is deleted too." [Cancel] [Delete];
  after delete, toast "Deleted “cohesive”" (no undo), select the next row.
- Empty state: `book-sprout` (xs) "No words yet — Look one up on the Learn tab and press Save."

## `/review` — Review
### Start (design: D05, M05)
- Daily review card: big due count, "words due today", "About M minutes · weakest words first"
  (same minutes rule as Learn), up to 4 due words as chips (weakest first, with `×N` badge when
  looked up more than once) + "+K more" chip, **Start review**. Data: stats `dueNow`, `duePreview`.
- When `dueNow = 0`: the card shows the `caught-up` illustration (xs), "All caught up", and
  "Next review: <tomorrow / Tue 21 Oct>, N words" from stats `nextDue`; the Start button is hidden.
- Practice card: scope segmented (This week · This month · All words · Weak words), questions
  segmented (5 · 10 · 20; default 10), **Start practice**, hint "N words this week/this month/in total/weak"
  (counts from `GET /api/words` counts; weak = min(30, total)). Disabled with hint "Save a few words first" when the scope has 0 words.
- Footer: New · Learning · Mastered counts.

### Question (design: D06, D07, M06, M07)
- Header row: session name ("Daily review" or "Practice · This week") + "3 of 7", **End session**, progress bar.
- MCQ: kind label (Meaning / Fill in the blank / Usage), prompt (blank drawn as a line), 4 options numbered 1–4.
  After choosing: correct option green with ✓, wrong pick red with ✗, others dimmed, explanation box
  with "Open word →" (opens the word card in a dialog), then **Next**. Answer is sent to `/api/quiz/answer` immediately.
- Recall: word large + part of speech + "Say the meaning in your head, then check." + **Show answer**.
  Revealed: meaning, Bangla line (respects the switch), one example, then **I didn't know** / **I knew it**.
- End-of-session retries (wrong answers asked once more) show a small "Retry" label next to the kind.
- **End session**: goes straight to the end screen with the questions answered so far (no confirm).

### Finished (design: D08, M08)
- `caught-up` illustration, score "5 / 7", summary line built on the client from the answer
  responses: "Nice work. N words moved up, M reached Mastered." (omit zero parts; all wrong →
  "Those were tough. They'll come back tomorrow.").
- "Missed · back tomorrow" list (words answered wrong, links to the word).
- Review mode with `remainingDue > 0`: primary **N more due · Continue**, secondary **Back to Learn**.
  Otherwise: hint "All caught up for today. Next review: …" (stats `nextDue`), primary **Practice more**
  (goes to the Practice card), secondary **Back to Learn**.

## Keyboard shortcuts (desktop; hints hidden on touch devices)
| Where | Key | Action |
|---|---|---|
| Anywhere | `/` | focus the Learn input (go to Learn if elsewhere) |
| Learn | `Enter` | send |
| Learn | `Ctrl+S` | save the latest word card (prevent the browser's save dialog) |
| Learn | `Esc` | clear the input |
| Review start | `Enter` | start review |
| Review | `1`–`4` | choose an option |
| Review | `Space` | show answer (recall) |
| Review | `Enter` / `Space` | next question (after answering) |
| Review (recall, revealed) | `1` / `2` | didn't know / knew it |
| Review end | `Enter` | the primary button |
The keyboard button in the header opens the shortcuts dialog (design: `states.html`).
