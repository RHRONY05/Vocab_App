# 02 — Architecture

## Stack
| Layer | Choice | Notes |
|---|---|---|
| Framework | Next.js 16, App Router, TypeScript strict | Read `node_modules/next/dist/docs/` before writing routing/middleware code: Next.js 16 has breaking changes (e.g. middleware is now `proxy.ts`). |
| Styling | Tailwind CSS v4 | Tokens in `globals.css`; light/dark via `prefers-color-scheme`. |
| UI primitives | shadcn/ui (Button, Input, Tabs, Dialog, Toast/sonner, Skeleton) | Only what is used. |
| DB + Auth | Supabase via `@supabase/supabase-js` + `@supabase/ssr` | Cloud project via Supabase MCP. |
| AI | Gemini via `@google/genai` | Model from `GEMINI_MODEL`. Before V3, check the current Gemini docs and pick a fast, low-cost model that supports structured JSON output (a "Flash"-class model). Record the choice in PROGRESS.md. |
| Validation | Zod | Shared schemas in `src/lib/schemas.ts`. |
| Tests | Vitest (unit + integration), Playwright (e2e, desktop + mobile), `@axe-core/playwright` | See `09-TESTING.md`. |
| Fonts + icons | `next/font/google` (Inter, Source Serif 4, Hind Siliguri), `lucide-react` | See `design/README.md`. |
| Hosting | Vercel (Hobby) via Vercel MCP | One daily cron (keepalive). |

Allowed dependencies: the ones above plus `clsx`, `tailwind-merge`, `sonner`, `@playwright/test`, `@axe-core/playwright`. Ask before adding anything else.
Package manager: npm. Node 20+.

`src/lib/env.ts` validates server env with Zod at startup and fails with a clear message if anything is missing.

On Vercel set: both `NEXT_PUBLIC_SUPABASE_*`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `ALLOWED_EMAIL`, `CRON_SECRET`, `APP_TIMEZONE`. **Not** the service-role key or the password.

## Auth
- Supabase email + password. One user, created in V2 by `scripts/create-user.ts` (service-role key, `auth.admin.createUser` with `email_confirm: true`). The password is random (24+ chars) and stored only in `.env.local` as `OWNER_PASSWORD`.
- Disable new sign-ups in Supabase Auth settings. If the MCP cannot change this setting, add it to "Human steps" in PROGRESS.md.
- Request proxy (`proxy.ts`): refresh the session; every page except `/login` requires a session, else redirect to `/login`. `/api/cron/keepalive` is excluded (it has its own secret check).
- Every API route calls `requireOwner()` (`src/lib/auth.ts`): no session or `email !== ALLOWED_EMAIL` → 401.
- RLS also limits every row to `auth.uid() = user_id`, so even a stray sign-up sees nothing.

## Data flow
```
Browser (client component)
  → fetch /api/... (JSON, Zod-validated)
    → requireOwner()  (Supabase server client with the user's cookie session)
    → lib/* pure logic  (quiz selection, SRS, date ranges)
    → Supabase (RLS as the user)   and/or   lib/ai.ts → Gemini (server only)
  ← JSON
```
The browser never talks to Gemini and never holds the Gemini key.

## Deploy (Vercel MCP)
- Private GitHub repo `RHRONY05/Vocab_App` (GitHub MCP or `gh`), push `main`.
- Create the Vercel project from that repo, set the env vars above, deploy. Production URL: the default `*.vercel.app` name (e.g. `vocab-rony.vercel.app`).
- `vercel.json` cron: `/api/cron/keepalive` once a day. Vercel sends `Authorization: Bearer <CRON_SECRET>`.
- After deploy: log in on the production URL and do one lookup to confirm Gemini works there.
